# ЮЗЫ — серверная версия Telegram Mini App

**Для запуска Telegram Mini App с ПК через временный HTTPS-туннель смотрите [TELEGRAM_LOCAL_START.md](TELEGRAM_LOCAL_START.md).** Этот сценарий использует настоящую Telegram-авторизацию и не требует Railway.


Использует существующий мобильный HTML/CSS. Все **итоги игры** генерируются и сохраняются на Python/Flask, а JavaScript только рисует интерфейс, посылает запросы и показывает анимации. Игровые `@юзы` **вымышленные**, это не принадлежащие кому-либо Telegram usernames.

## Локальный запуск (Windows, VS Code)

1. Распакуйте ZIP. Откройте **корневую папку**, где лежит `app.py`.
2. В терминале PowerShell:

   ```powershell
   py -m venv .venv
   .\.venv\Scripts\Activate.ps1
   python -m pip install -r requirements.txt
   $env:LOCAL_DEMO="1"
   python app.py
   ```

   При запрете активации среды можно использовать `\.venv\Scripts\python.exe` вместо `python`.
3. Откройте **http://127.0.0.1:5000**. Для тестового браузера включён `LOCAL_DEMO=1` — через localhost создаётся отдельный демонстрационный игрок с серверным балансом.
4. Протестируйте одиночную крутку, ×5, выбор "Продать"/"В инвентарь", магазин, достижения, профиль и рынок. Сброс аккаунта доступен в настройках.

Внимание: старая `localStorage` с балансом **не импортируется** (она не заслуживает доверия). У каждого нового игрока на сервере 500 $. База для локальной разработки — `yuzy_dev.sqlite3`, который не нужно коммитить в Git.

## Развёртывание Telegram Mini App через Railway

1. Создайте бота у [@BotFather](https://t.me/BotFather) через `/newbot`. Токен никому не пересылайте.
2. Загрузите содержимое проекта в приватный GitHub-репозиторий. Не добавляйте `.env` и базу `*.sqlite3`.
3. В Railway создайте сервис **PostgreSQL** и сервис **Deploy from GitHub** для Flask-проекта.
4. В **Variables** Flask-сервиса установите:

   | Переменная | Значение |
   | --- | --- |
   | `APP_ENV` | `production` |
   | `BOT_TOKEN` | токен из BotFather (секрет!) |
   | `SESSION_SECRET` | случайная длинная строка, например результат `python -c "import secrets; print(secrets.token_hex(32))"` |
   | `DATABASE_URL` | ссылка на переменную PostgreSQL, например `${{Postgres.DATABASE_URL}}` (указание точного имени зависит от имени сервиса) |

   `LOCAL_DEMO` **НЕ задавать** в облаке. Без `BOT_TOKEN`, `DATABASE_URL`, `SESSION_SECRET` сервис в production остановится с понятной ошибкой — это сделано специально. При наличии Railway environment обычный режим разработки тоже отключён.
5. Команда запуска (уже в `Procfile`):

   ```bash
   gunicorn --workers 1 --threads 4 --bind 0.0.0.0:${PORT:-8000} app:app
   ```

6. Railway → Service → Settings → Networking → Generate Domain. Убедитесь, что `https://адрес/health` отвечает `{ "status": "ok" }`. Открытый в **обычном браузере** сайт в production покажет отказ авторизации: **это нормально**, игровой API доступен только с проверенным Telegram `initData`.
7. BotFather → `/mybots` → ваш бот → `Bot Settings` → `Configure Mini App` → `Enable Mini App`. Укажите **точный HTTPS URL** Railway. Опционально задайте Menu Button с текстом «Играть» на том же URL.
8. Откройте бота в Telegram, нажмите Launch App, прокрутите юз. Проверяйте Server Logs Railway при ошибках.

**Важно:** Railway без постоянной базы/тома не сохраняет локальный файл SQLite надёжно между пересозданиями сервиса. Для общего запуска используйте PostgreSQL.

## Правила экономики (изменение относительно старого JS)

В исходной игре цена выпадения сразу начислялась и при этом тот же юз можно было сохранить, а затем продать вторично. Здесь это исправлено:

- За крутку сервер снимает игровую стоимость выбранного режима и длины.
- Одна крутка даёт один **неразобранный результат**. **Продать** → цена начисляется на счёт, результат исчезает. **В инвентарь** → юз становится предметом, деньги пока не начисляются; его можно продать позже. **Двойной выплаты нет**.
- На следующей крутке предыдущие неразобранные результаты автоматически продаются (чтобы не оставлять очередь без ограничения); на экране это явно объяснено. Их можно разобрать в «Инвентаре» перед следующей круткой.
- ×5 создаёт пять серверных результатов; для каждого можно выбрать действие. Режимы "авто-инвентарь" сохраняют подходящие юзы, неподходящие продают автоматически.
- При переполненном инвентаре нельзя получить новые предметы. В режиме авто-инвентаря такие результаты продаются.
- Установленный в профиле юз защищён от продажи до снятия.
- Рынок — реальные объявления **за виртуальные $**, можно покупать юзы других игроков (транзакционно). Это не рынок Telegram Stars.
- Специальные **CHEAT** команды доступны **только на localhost с LOCAL_DEMO=1**. На Railway их нет.

## Где что находится

| Файл | Назначение |
| --- | --- |
| `app.py` | Flask-роуты, авторизация, денежные транзакции, инвентарь, маркет, достижения |
| `engine.py` | Стоимость круток, серверная генерация юзов, редкости, выплаты, достижения, уровни |
| `game.py` | Сохранившиеся Python-функции Велимира: генераторы и расчёт множителя (вызываются `engine.py`) |
| `storage.py` | SQLite/PostgreSQL, таблицы игроков, выпадений, предметов, защита от повторных запросов |
| `security.py` | Проверка подписанного Telegram `initData` и срока действия |
| `game_config.json` | Режимы, уровни, достижения, коэффициенты из предыдущего JS |
| `templates/index.html` | Исходный мобильный интерфейс, добавлена кнопка продажи |
| `static/script.js` | Вывод данных от Python, анимации, действия кнопок, без авторитетной экономики |

## Маршруты API

| Метод и URL | Действие |
| --- | --- |
| `GET /api/config` | Настройки и каталог режимов |
| `GET /api/state` | Баланс, уровни, достижения, инвентарь, ожидающие крутки, ваши лоты |
| `GET /api/quote` | Серверная стоимость крутки с параметрами mode, length, count |
| `POST /api/spin` | Транзакция списания и генерация 1 или 5 результатов; обязательный `request_id` предотвращает двойную крутку |
| `POST /api/rolls/<id>/collect` | Забрать конкретный результат |
| `POST /api/rolls/<id>/sell` | Продать конкретный результат |
| `POST /api/rolls/sell-pending` | Продать ожидающие результаты |
| `GET /api/inventory` | Ваш инвентарь |
| `POST /api/inventory/<id>/sell`, `/api/inventory/sell-all` | Продажа предметов за виртуальную валюту |
| `POST /api/profile/install`, `/api/profile/uninstall` | Установить или снять юз |
| `POST /api/settings` | Выбор auto_level 0–4 |
| `POST /api/achievements/<id>/claim` | Однократная выдача заслуженной награды |
| `GET /api/market`, `POST /api/market/list`, `POST /api/market/<id>/cancel`, `POST /api/market/<id>/buy` | Рынок за виртуальную валюту |
| `POST /api/reset` | Удаление прогресса текущего игрока с явным подтверждением |
| `POST /api/dev/cheat` | Только localhost; отключён в production |
| `GET /health` | Проверка жизни сервера |

### Авторизация

Фронтенд передаёт `Telegram.WebApp.initData` в заголовке `X-Telegram-Init-Data`. Flask проверяет HMAC-SHA256 с `BOT_TOKEN`, не принимает чужой `user_id` из тела запроса и отклоняет старые `initData` (старше 24 часов). При обычном публичном открытии сайта без Telegram доступ к игровым API закрыт.

### Что ещё НЕ реализовано

- **Telegram Stars, реальные платежи и выдача покупок:** сознательно не включены. Для них потребуется безопасное выставление инвойса в `XTR`, серверная обработка подтверждённых `successful_payment`, учёт refund и idempotent выдача товаров. Не включайте платёжные кнопки до реализации проверки.
- Ограничение частоты запросов для большого публичного запуска, антибот-система, резервное копирование БД, отдельные DB-миграции. Сейчас это пригодный для тестирования MVP, но не завершённая платёжная система.
- Старый файл фронтенда был сильно минифицирован. Основные экраны и оформление сохранены, отдельные сверхдлинные эффекты появления редкости упрощены для надёжной интеграции.

Официальная документация Telegram по проверке `initData`: https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app
